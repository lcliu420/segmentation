## 第 1 页：为什么在 CSWin-UNet 上加频率注意力

### 本页讲述目标

说明当前改造的出发点：医学分割中的边界细、弱、容易混入伪边界，因此希望在不破坏 CSWin-UNet 主干的基础上，对 skip feature 做频率增强。

### 口播稿

这一页主要介绍我为什么要在 CSWin-UNet 上加入频率注意力。

在医学图像分割任务中，目标区域的边界往往比较细，而且形态不规则。尤其是病灶边缘或者组织交界区域，模型很容易出现边界不清、局部断裂，或者把一些纹理噪声误分成伪边界的问题。

CSWin-UNet 本身是一个比较强的 Transformer-UNet 基底，它通过 CSWin Transformer Block 获取更强的上下文信息，同时保留了 U-Net 的 skip connection 结构。但是原始 CSWin-UNet 并没有专门针对频率信息或者边界信息做显式增强。

我选择 CSWin-UNet 作为基底，主要不是因为它已经解决了频率增强和伪边界抑制问题，而是因为它适合作为一个稳定且结构清晰的改造平台。第一，它保留了 U-Net 的多尺度 skip connection，x1、x2、x3 这些特征层级很明确，便于我把频率增强模块插入到不同 skip 上做消融。第二，CSWin Transformer Block 能通过横向和纵向条带注意力建模更长程的上下文信息，为后续边界判断提供更强的语义基础。第三，decoder 中的 CARAFE 上采样本身也更关注内容感知的特征重组，有利于恢复空间细节。相反，如果选择一个本身已经包含复杂边界分支或频率模块的网络，后续就很难说清楚提升到底来自原模型还是我加入的模块。

所以我的设计问题是：能不能只在 skip feature 上做一个轻量改造，让传给 decoder 的特征里保留更多有用的高频边界，同时利用低频结构信息减少噪声和伪边界的干扰。基于这个思路，我引入了 PFESA 的 FFT 高频/低频解耦机制，把它接到 x1、x2、x3 三条 skip feature 上做组合消融。

### 过渡句

接下来我先说明这两个模块分别来自哪两篇论文，以及它们在我当前模型里各自承担什么作用。

### 可强调点

- 当前改造不是重新设计整个网络，而是在 CSWin-UNet 基底上做 skip feature 级别的轻量增强。
- 课题关键词是：频率增强、边界细节、伪边界抑制。
- 选择 CSWin-UNet 的理由可以概括为：强基底、skip 插入点清晰、全局上下文建模能力强，同时原模型缺少显式频率/伪边界机制，适合做课题模块验证。

## 第 2 页：两篇论文分别提供了什么

### 本页讲述目标

说明 CSWin-UNet 是主干基底，PFESA 是后加的频率注意力模块，避免把两篇论文的贡献混在一起。

### 口播稿

这一页主要说明我当前模型的两个来源。

左边是 CSWin-UNet 论文，它提供的是整个分割网络的基底结构。具体来说，它包括 convolutional token embedding、CSWin Transformer Block、U-shaped encoder-decoder 结构，以及 decoder 里的 CARAFE 上采样和 skip connection 融合。

右边是 PFESA 论文，它提供的是一个 parameter-free 的频率注意力模块。PFESA 的核心思想是先用 FFT 把特征分解到频域，再区分高频和低频成分。高频分支对应 edge attention，更关注边界和细节；低频分支对应 structure attention，更关注整体结构和低频形态信息。

所以我当前做的不是把 PFESA 整个网络替换进来，也不是说 PFESA 是 CSWin-UNet 原始论文里的模块。更准确地说，是保留 CSWin-UNet 作为主网络，只把 PFESA 的频率注意力思想接到 CSWin-UNet 的 skip feature 上。

### 过渡句

明确了模块来源之后，下面这一页就是当前模型的整体结构，以及公式上这两个模块分别对应什么。

### 可强调点

- CSWin-UNet：提供主干网络和 decoder 结构。
- PFESA：提供频率解耦和无参数注意力。
- 当前模型是组合迁移，不是完整替换网络。

### 本页讲述目标

解释当前模型的数据流，以及右侧三个公式块分别对应 CSWin attention、PFESA 频率解耦和 PFESA 注意力计算。

### 口播稿

下面我按照 **`baseline+PFESA` 代码真实执行流程**，结合你这张图，从输入到输出完整解释一遍。

这张图整体表达的是：

```text
CSWin-UNet 主体 + 在 x1/x2/x3 三条 skip connection 上加入 PFESA
```

也就是 `pfesa_skip_mode="x123"`。

## 1. 输入与 Token Embedding

图最左上角是输入图像。代码中输入一般是：

```text
[B, 3, 224, 224]
```

在 `cswin_unet.py` 中首先经过：

```python
self.stage1_conv_embed = nn.Sequential(
    nn.Conv2d(in_chans, embed_dim, 7, 4, 2),
    Rearrange('b c h w -> b (h w) c', h=img_size // 4, w=img_size // 4),
    nn.LayerNorm(embed_dim)
)
```

对应图里的：

```text
Convolutional Token Embedding
7x7 conv, stride 4
224x224 -> 56x56
```

作用是把原图从空间图像变成 token 序列：

```text
[B, 3, 224, 224]
-> [B, 64, 56, 56]
-> [B, 56*56, 64]
```

所以 Stage 1 的输入 token 分辨率是 `56x56`，通道数是 `64`。

## 2. Encoder 主干部分

左侧蓝色模块就是 CSWin-UNet 的 encoder。

配置文件里写的是：

```yaml
DEPTH: [1, 2, 9, 1]
EMBED_DIM: 64
NUM_HEADS: [2, 4, 8, 16]
```

所以四个 encoder stage 分别是：

```text
Stage 1: CSWin Transformer Block x1
Stage 2: CSWin Transformer Block x2
Stage 3: CSWin Transformer Block x9
Stage 4: CSWin Transformer Block x1
```

这和图中左侧四个蓝色框一致。

每个 stage 后面的粉色 `Convolution Layer / Merge` 对应代码里的：

```python
self.merge1 = Merge_Block(curr_dim, curr_dim * 2)
self.merge2 = Merge_Block(curr_dim, curr_dim * 2)
self.merge3 = Merge_Block(curr_dim, curr_dim * 2)
```

它的作用是下采样并增加通道数：

```text
Stage 1 输出: 56x56, C=64
Merge 1 后: 28x28, C=128

Stage 2 输出: 28x28, C=128
Merge 2 后: 14x14, C=256

Stage 3 输出: 14x14, C=256
Merge 3 后: 7x7, C=512

Stage 4 Bottleneck: 7x7, C=512
```

## 3. x1/x2/x3 三条 skip 是怎么来的

代码中 `forward_features` 里会保存三条 skip：

```python
self.x1 = self.apply_pfesa_skip(x, "x1")
x = self.merge1(x)

self.x2 = self.apply_pfesa_skip(x, "x2")
x = self.merge2(x)

self.x3 = self.apply_pfesa_skip(x, "x3")
x = self.merge3(x)
```

所以：

```text
x1 = Stage 1 输出，56x56, C=64
x2 = Stage 2 输出，28x28, C=128
x3 = Stage 3 输出，14x14, C=256
```

这正好对应图中的三条虚线 skip connection。

非常关键的一点是：**PFESA 只作用在保存给 decoder 的 skip 上，不作用在 encoder 主干继续下采样的路径上。**

例如：

```python
self.x1 = self.apply_pfesa_skip(x, "x1")
x = self.merge1(x)
```

这里 `self.x1` 是给 decoder 用的增强 skip，但 `merge1(x)` 仍然使用原始 `x` 继续往下走。因此图中 PFESA 画在虚线 skip 上是对的，不能画在左侧竖直 encoder 主路径上。

## 4. x123 表示什么

在 `baseline+PFESA` 中，训练脚本会把参数传给模型：

```python
CSwinUnet(
    config,
    img_size=args.img_size,
    num_classes=args.num_classes,
    pfesa_skip_mode=args.pfesa_skip_mode,
    pfesa_base_ratio=args.pfesa_base_ratio,
)
```

当设置为：

```text
pfesa_skip_mode = x123
```

代码中会执行：

```python
self.pfesa_skip_layers = set(pfesa_skip_mode[1:])
```

也就是：

```text
"x123" -> {"1", "2", "3"}
```

所以：

```text
x1 使用 PFESA
x2 使用 PFESA
x3 使用 PFESA
```

图中三条 skip 上分别有：

```text
Expanded PFESA x1
PFESA x2
PFESA x3
```

这和代码一致。图里只把 `x1` 的 PFESA 展开，是为了展示 PFESA 内部结构；实际上代码中 `x1/x2/x3` 用的是同一种 `TokenPFESA + PFESA` 逻辑。

## 5. PFESA 内部结构

图中央展开的是 `Expanded PFESA x1`，对应代码中的两个类：

```python
class TokenPFESA(nn.Module)
class PFESA(nn.Module)
```

由于 CSWin-UNet 的 skip 是 token 形式：

```text
[B, L, C]
```

所以 `TokenPFESA` 会先把它转回二维特征图：

```text
[B, L, C] -> [B, C, H, W]
```

例如 x1：

```text
[B, 56*56, 64] -> [B, 64, 56, 56]
```

然后进入 PFESA。

PFESA 内部做的是：

```text
Input skip X
-> FFT
-> Frequency Decoupling
-> Low-frequency feature
-> High-frequency feature
```

代码中对应：

```python
x_freq = torch.fft.fftn(x, dim=(-2, -1))
x_freq = torch.fft.fftshift(x_freq, dim=(-2, -1))

low_freq_mask = self._create_low_freq_mask(h, w, device=x_freq.device)
high_freq_mask = 1 - low_freq_mask

low_freq = torch.abs(torch.fft.ifftn(x_freq * low_freq_mask, dim=(-2, -1)))
high_freq = torch.abs(torch.fft.ifftn(x_freq * high_freq_mask, dim=(-2, -1)))
```

图里画了 `FFT -> FD -> High-frequency / Low-frequency`，这是对的。严格来说，代码里高频和低频分离之后还有一次 `iFFT` 回到空间域，图里省略了这个细节，作为架构图可以接受；如果你想更严谨，可以在 FD 后面补一个小的 `iFFT` 标注。

然后 PFESA 分成两个注意力：

```text
High-frequency -> EA Edge Attention
Low-frequency -> SA Structure Attention
```

代码中：

```python
out_att = self._structure_attention(low_freq) + self._edge_attention(high_freq)
out_att = self.activation(out_att)
return out_att * x
```

所以图里的：

```text
EA + SA
-> Sigmoid
-> Multiply with original X
-> Refined x1 skip
```

也是和代码一致的。

最后 `TokenPFESA` 再把特征转回 token：

```text
[B, C, H, W] -> [B, L, C]
```

然后送给 decoder concat。

## 6. Bottleneck 到 Decoder Stage 4

左下角 `Stage 4 Bottleneck` 经过实线连接到右下角 `Decoder Stage 4`。

这部分没有 PFESA。

代码中 encoder 最后：

```python
for blk in self.stage4:
    x = blk(x)

x = self.norm(x)
return x
```

然后 decoder 开始：

```python
for blk in self.stage_up4:
    x = blk(x)
```

所以图中的底部实线：

```text
Stage 4 Bottleneck -> Decoder Stage 4
```

是主干 bottleneck 连接，不是 skip connection，也不属于 `x123` 的 PFESA 范围。

## 7. Decoder 解码过程

右侧是 decoder，对应代码中的 `forward_up_features`。

流程是从下往上：

```python
for blk in self.stage_up4:
    x = blk(x)

x = self.upsample4(x)
x = torch.cat([self.x3, x], -1)
x = self.concat_linear4(x)
```

对应图中：

```text
Decoder Stage 4
-> CARAFE Layer 2x
-> concat PFESA-refined x3
-> Decoder Stage 3
```

形状大致是：

```text
7x7, C=512
-> CARAFE 2x
-> 14x14, C=256
-> concat x3: 256 + 256 = 512
-> Linear: 512 -> 256
```

然后第二次：

```python
x = self.upsample3(x)
x = torch.cat([self.x2, x], -1)
x = self.concat_linear3(x)
```

对应：

```text
Decoder Stage 3
-> CARAFE Layer 2x
-> concat PFESA-refined x2
-> Decoder Stage 2
```

形状：

```text
14x14, C=256
-> 28x28, C=128
-> concat x2: 128 + 128 = 256
-> Linear: 256 -> 128
```

第三次：

```python
x = self.upsample2(x)
x = torch.cat([self.x1, x], -1)
x = self.concat_linear2(x)
```

对应：

```text
Decoder Stage 2
-> CARAFE Layer 2x
-> concat PFESA-refined x1
-> Decoder Stage 1
```

形状：

```text
28x28, C=128
-> 56x56, C=64
-> concat x1: 64 + 64 = 128
-> Linear: 128 -> 64
```

注意，代码中的 concat 顺序是从深到浅：

```text
先融合 x3
再融合 x2
最后融合 x1
```

这和图右侧从下往上解码是一致的。

## 8. 最终输出

decoder 最后经过：

```python
self.upsample1 = CARAFE4(curr_dim, 64)
self.output = nn.Conv2d(in_channels=embed_dim, out_channels=self.num_classes, kernel_size=1, bias=False)
```

对应图中右上角：

```text
CARAFE Layer 4x
-> 1x1 Conv / Linear Projection
-> Segmentation Mask
```

也就是：

```text
[B, 56*56, 64]
-> CARAFE4
-> [B, 64, 224, 224]
-> 1x1 Conv
-> [B, 2, 224, 224]
```

因为当前是二分类分割，所以 `num_classes=2`。

## 总结

这张图和 `baseline+PFESA` 的代码主体是对应的。

最准确的描述是：

```text
CSWin-UNet + PFESA-x123 是在原始 CSWin-UNet 的三条 skip connection 上加入 PFESA。
x1、x2、x3 分别来自 encoder Stage 1、Stage 2、Stage 3。
PFESA 对 skip feature 做 FFT 高频/低频解耦，生成 Edge Attention 和 Structure Attention，再乘回原始 skip feature。
增强后的 skip feature 再送入 decoder，与 CARAFE 上采样后的特征 concat。
encoder 主干、Stage 4 bottleneck、decoder CSWin blocks 和 CARAFE 上采样结构均保持原始 CSWin-UNet 不变。
```

唯一可以进一步严谨化的小点是：图中 PFESA 展开部分如果补上 `iFFT`，会更贴近代码；另外底部英文说明里 `bottleneck` 拼写确认一下即可。

### 过渡句

为了更清楚地说明 PFESA 在 skip feature 里具体做了什么，下一页我把 PFESA 的内部流程单独展开。

### 可强调点

- 图中 PFESA 是后加在 skip 上的模块，不是 CSWin-UNet 原论文自带模块。
- PFESA 只改变 decoder 接收到的 skip，不改变主干 encoder。
- 公式不用逐项推导，重点讲清楚每个公式对应的模块作用。

## 第 4 页：PFESA 内部流程

### 本页讲述目标

说明 PFESA 如何从 token 到 feature map，再经过 FFT、高低频分支和注意力融合，最后回到 token 形式。

### 口播稿

这一页进一步展开 PFESA 的内部流程。

因为 CSWin-UNet 里的特征是 token 形式，所以在送入 PFESA 之前，需要先把 skip feature 从 `B x L x C` reshape 回二维特征图，也就是 `B x C x Hs x Ws`。

然后 PFESA 对这个二维特征图做 FFT，把它转到频域。在频域中，低频部分主要对应整体结构和形态信息，高频部分主要对应边界、纹理和局部细节。

接下来，低频分支会形成 structure attention，高频分支会形成 edge attention。两个注意力相加之后经过 Sigmoid，形成最终的 attention map。这个 attention map 再和原始 skip feature 做逐元素相乘，从而得到增强后的 skip feature。

最后，增强后的特征再 reshape 回 `B x L x C` 的 token 形式，送入后续 decoder 进行 concat 和上采样。

这里还有一个重要特点：PFESA 本身是不引入额外可训练参数的。因此它相对轻量，也比较适合先作为 skip feature 的频率增强模块来做消融验证。

### 过渡句

在明确模型结构之后，最后一页展示的是我在 new_dataset 上做的消融实验结果。

### 可强调点

- 高频分支对应边界和细节增强。
- 低频分支对应结构保持，并有助于减少噪声或伪边界干扰。
- PFESA 是 parameter-free，不额外增加训练参数。

## 第 5 页：outputs_new 验证集结果

### 本页讲述目标

解释不同 skip 组合的验证集表现，给出当前阶段的主要观察：x123 综合最优，x13 边界指标最优，x1/x3 单独使用不稳定。

### 口播稿

这一页是基于 `outputs_new` 的验证集 best epoch 结果。需要先说明一下，这里的结果来自清洗后的 new_dataset，并且是验证集结果，还不是最终 test 结果，所以不能直接作为最终泛化结论。

从 Dice 指标看，x123 是当前综合表现最好的配置。它的 Val Dice 是 0.885479，相比 baseline 的 0.884466，有一个小幅提升，提升值大约是 0.001。IoU 和 HD95 也有一定改善。这说明同时在 x1、x2、x3 三条 skip feature 上加入 PFESA，整体上比只加单条 skip 更稳定一些。

如果单独看边界指标，x13 的 Boundary IoU 是最高的，为 0.340406，高于 baseline 的 0.338314。这说明浅层 x1 的细节信息和深层 x3 的语义信息结合后，可能对边界区域有一定帮助。

但是也可以看到，x1 和 x3 单独加入 PFESA 时反而低于 baseline。这个现象也比较重要，说明频率增强不是简单地加在哪里都有效。尤其是 x1 这种浅层特征，虽然边界细节多，但噪声和伪边界也更多，单独增强高频信息可能会带来干扰。

所以当前阶段我更倾向于把 x123 作为综合表现较好的配置，把 x13 作为边界指标上的一个有价值观察。后续还需要在 test split 上进一步验证，才能判断它们是否具有稳定泛化能力。

### 过渡句

以上就是目前基于 CSWin-UNet 和 PFESA skip 增强得到的结构设计和初步消融结果。

### 可强调点

- x123 综合最优，但提升幅度较小，不能夸大。
- x13 边界指标最优，可以作为后续边界增强方向的线索。
- 当前是验证集 best epoch 结果，不是最终 test 结论。
- x1/x3 单独使用不稳定，说明伪边界和浅层噪声需要进一步控制。
